# CHRONA Doctor Portal (Prototype)

**Demonstration prototype. Synthetic data only. Not for clinical use. Not a
substitute for professional medical judgment.**

A multi-patient doctor portal demo built to prove one mechanism: given two
or more documents from the same (fictional) patient across visits, the
system generates a cited, accurate "what changed" brief and flags
illustrative drug interactions — with generated briefs cached in SQLite so
repeat views don't re-call the LLM unless the patient's underlying data has
actually changed.

It is a capstone-project demo (DBA, Cohort 11, Group 5) for a Generative AI
venture concept called **CHRONA** — a longitudinal patient card aimed at
independent Indian specialty clinics. This prototype demonstrates the core
mechanism behind Patent Claim 1 (inter-visit delta briefing) and, partially,
Claim 4 (cross-specialist interaction detection) in miniature. It is **not**
the full product.

## Two deployable versions in this repo

| | Frontend | Backend | Hosting |
|---|---|---|---|
| **Recommended** — `index.html` + `server.py` | Pixel-perfect custom HTML/CSS/JS doctor-portal design | Flask API | Docker (Hugging Face Spaces) |
| Legacy — `app.py` | Streamlit's native widgets, custom CSS applied on top | Streamlit (same process) | Streamlit Community Cloud |

Both share the same data layer (`db.py`, `seed_data.py`, `interactions.py`,
`prompts.py`) and the same cache-first generation mechanism. The Streamlit
version was the first build; it was replaced as the primary demo because
Streamlit's native component chrome (buttons, containers, metrics) couldn't
fully match the intended design — stat tiles, avatar gradients, badges, and
icon styling all fell short of the mockup. The Flask + static-HTML version
keeps the original design byte-for-byte and wires its existing JavaScript to
real endpoints instead.

## What this demo does

- **Login gate** with three demo doctor accounts (shown on the login
  screen) — a UX gate for the demo, not real authentication.
- **8 synthetic patients**, each with structured vitals, active conditions,
  labs, a cross-specialist medication table, care team, and 1-4 visit
  documents seeded into a local SQLite database (`chrona.db`, created on
  first run).
- **Dashboard** with live stat tiles (patient count, DDI alert count,
  briefs generated) and a safety-alerts panel, all computed from the DB.
- **Patient Card** per patient with five tabs:
  - **Overview** — vitals, conditions, labs, medications by prescriber, care team.
  - **Since Last Visit** — generates a cited delta brief via the LLM,
    comparing the earliest visit on file to the most recent one(s).
  - **Timeline** — every visit/report on file for that patient.
  - **DDI Alerts** — illustrative cross-specialist interaction checks
    against that patient's medication list, with mechanism/severity detail.
  - **ADR Report** — a mock adverse-drug-reaction report form (nothing is
    actually submitted anywhere).
- **Cache-first generation**: each patient's documents are hashed; a brief
  is only regenerated by calling Claude when that hash changes (i.e. a new
  report/visit/prescription was added for that patient) — otherwise the
  cached brief is served straight from SQLite with no API call.
- Visually flags any generated sentence that lacks a source citation
  (hover-tooltip citations in the HTML version, inline warning icons in the
  Streamlit version), and styles interaction flags as advisory (amber tones,
  "for clinician review"), never alarming.

## Explicitly out of scope

- Real document upload via WhatsApp/email/scanner, or vision-based
  extraction from scanned images
- A real vector database or retrieval pipeline
- ABDM/FHIR/EMR integration of any kind
- Real authentication, multi-tenant access control, or a production database
- Any payment, billing, or subscription logic
- A licensed clinical drug-interaction database (RxNorm/CDSCO-mapped)
- Real PvPI/CDSCO submission (the ADR tab is a mock form only)

## Running locally

**Flask + HTML version (recommended)**
```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...
python server.py
# open http://localhost:7860
```

**Streamlit version (legacy)**
```bash
pip install -r requirements.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
# edit .streamlit/secrets.toml and add your ANTHROPIC_API_KEY
streamlit run app.py
```

The SQLite database (`chrona.db`) is created and seeded automatically on
first run for either version — no manual setup needed.

## Deploying (free tier)

**Hugging Face Spaces — Docker SDK (for the Flask + HTML version)**
1. Push this repo to a public GitHub repository (already done).
2. Go to [huggingface.co/new-space](https://huggingface.co/new-space).
3. Pick an owner/name, set **SDK = Docker**, visibility = Public, then create the Space.
4. In the Space's **Files** tab, link/import from this GitHub repo (or use
   `git remote add space <space-git-url>` and `git push space main` from a
   local clone) — the Space will build the `Dockerfile` in this repo automatically.
5. In Space **Settings → Repository secrets**, add `ANTHROPIC_API_KEY`.
6. Wait for the build to finish — the Space serves on port 7860 per the Dockerfile.

**Streamlit Community Cloud (for the Streamlit version)**
1. Go to [share.streamlit.io](https://share.streamlit.io), connect this repo,
   and deploy `app.py`.
2. In the app's Settings → Secrets, add:
   ```toml
   ANTHROPIC_API_KEY = "sk-ant-..."
   ```

Note: on either free tier, the filesystem (and so `chrona.db`) is not
guaranteed to persist across restarts/redeploys — it reseeds automatically
from `seed_data.py` on next boot, so previously generated (non-cached)
briefs would need regenerating. This is expected for a free-tier demo.

## Guardrails demonstrated (lightweight)

1. **Source citation enforcement** — any sentence in the generated brief
   without a `[Source: ...]` tag is visually flagged (a warning marker in
   the HTML version, a warning icon in the Streamlit version) instead of
   being silently accepted.
2. **Advisory-only labelling** — interaction flags are styled as
   informational (amber tones, "for review"), never as directive or
   alarming, and every DDI/ADR panel states clinician confirmation is
   required.

These are illustrative guardrail touches, not the full guardrail suite from
the CHRONA product design (which also includes PII masking, namespace
isolation, and consent-token gating — out of scope for this prototype).

## Data notice

Every patient, document, medication, lab value, and clinical detail in this
repository is fabricated for demonstration purposes. No real patient data
was used, requested, or processed anywhere in this project.
